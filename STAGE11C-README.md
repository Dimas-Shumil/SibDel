# SibDel — этап 11C: уведомления и навигация PWA

Основа: этап 11B, сохранённый локально и отправленный в Dimas-Shumil/SibDel коммитом `bc8dec0`.
Этот ZIP содержит только новые и изменённые файлы 11C. Для чистого старого проекта сначала необходимы 11A и 11B.
Новых зависимостей, миграций, переменных окружения и VAPID-ключей в 11C нет.
Существующие `.env`, загрузки и записи базы патч не перезаписывает.

## Что показал аудит

- В 11B уже существует `CustomerNotification` с `readAt`, `openedAt`, категорией, временем и внутренней ссылкой. События заказов и подписок записываются SQL-триггерами в той же транзакции, что и событие. Очередь PUSH работает отдельно; доставка не требуется для сохранения истории.
- Кабинет уже использует один HTML-шаблон, собственный маршрутизатор и боковое меню. Новый раздел встроен в них, отдельный кабинет не создаётся.
- Настройки категорий, устройства и отдельное рекламное согласие уже реализованы в `/account/settings`. Здесь оставлены те же настройки и серверные проверки.
- Корзина и избранное синхронизируются через существующий `SibDelCommerce` и API. Повтор заказа и загрузка актуального отдельного заказа уже есть. Системы корзины, цен и заказов не заменяются.
- Мобильная шапка и выдвижное меню уже есть; постоянной нижней панели нет. Новая панель нужна для пяти частых переходов в установленном приложении. В обычном браузере, на широком экране, в checkout, авторизации и админке она отсутствует.

## Реализовано

`/account/notifications`:

- история по 20 сообщений с кнопкой «Показать ещё» и курсором по ID;
- категории «Заказы», «Подписка», «Предложения», фильтр непрочитанных;
- счётчик непрочитанных в меню кабинета;
- отдельная отметка прочтения, переход по внутренней ссылке, отметка всех сообщений;
- кнопка перехода к существующим настройкам PUSH и рекламы;
- состояния загрузки, отсутствия сообщений, сетевой ошибки и повторной загрузки;
- сохранение истории при выключенных PUSH, отсутствии устройства и недоставке;
- отдельные поля: чтение в кабинете меняет только `readAt`, не статистику `openedAt` реального клика по PUSH;
- отсутствие автоматического прочтения при открытии списка: пользователь сам отмечает сообщение или открывает его;
- «Отметить всё» действует на все категории до верхней границы последней загрузки. Сообщения, появившиеся после неё, остаются новыми. Фильтр не превращает эту кнопку в отметку только текущей страницы;
- тесты владельца категории TEST в клиентской истории не показываются.

API:

| Метод и путь | Назначение |
| --- | --- |
| GET `/api/account/notifications` | Список: `before`, `limit` 1–50, `category`, `unread=true/false` |
| GET `/api/account/notifications/unread-count` | Общее число непрочитанных сообщений клиента |
| PATCH `/api/account/notifications/:id/read` с `{}` | Идемпотентная отметка одного сообщения |
| POST `/api/account/notifications/read-all` с `{throughId: NUMBER}` | Идемпотентная отметка до границы загрузки |

Все операции требуют действительной клиентской сессии и роли CUSTOMER. Идентификатор пользователя берётся только из сессии; чужие ID не дают читать или менять чужие записи. Ответы `no-store`, для записи действует существующая CSRF-защита, параметры проверяются строго. DTO не содержит ключей PUSH, endpoint, eventKey, userId или статистики отправок. Ошибки хранилища не раскрывают SQL. Ссылки и изображения проходят существующую проверку допустимых внутренних путей; текст выводится через `textContent`.

Нижняя навигация:

- «Главная», «Каталог», «Акции», «Корзина», «Профиль» ведут на существующие маршруты;
- только standalone/fullscreen PWA на ширине до 767px; установка без регистрации сохранена;
- активная страница доступна через `aria-current`, все цели касания не меньше 44px;
- счётчик корзины использует `SibDelCommerce`, включая сохранённую корзину после перезагрузки;
- добавлен `viewport-fit=cover` в публичные HTML, отступы safe-area слева, справа и снизу;
- панель скрывается при вводе в поле/открытом редакторе; содержимое имеет нижний отступ;
- существующая фиксированная кнопка оформления корзины и сообщения располагаются над панелью;
- при переходах внутри кабинета и истории браузера активный пункт обновляется;
- в offline остаётся прежняя нейтральная страница: история и персональные страницы не кешируются.

SW получает версию `11c-1`, поскольку изменён кешируемый PWA CSS. Обновление по-прежнему ждёт закрытия всех окон сайта и приложения, без принудительной перезагрузки или `skipWaiting`.

## Windows CMD — рекомендуемая установка с копией исходников

Сначала остановить локальный `npm run dev` через Ctrl+C. `git status --short` перед установкой должен быть пустым; коммит 11B уже сохранён.
Распаковать ZIP в отдельную папку `C:\Temp\sibdel-stage11c`, а не внутрь проекта. В ней непосредственно должны находиться `STAGE11C-FILES.json`, `scripts`, `site` и другие файлы патча.

```cmd
cd /d C:\Users\ШУМ\WORKS\sibDel
git status --short
node C:\Temp\sibdel-stage11c\scripts\stage11c-patch.mjs check "C:\Users\ШУМ\WORKS\sibDel"
node C:\Temp\sibdel-stage11c\scripts\stage11c-patch.mjs apply "C:\Users\ШУМ\WORKS\sibDel" "C:\Temp\sibdel-before-stage11c"
node C:\Temp\sibdel-stage11c\scripts\stage11c-patch.mjs verify "C:\Users\ШУМ\WORKS\sibDel"
npm run test:unit
npm run dev
```

Папка резервной копии должна быть новой и находиться вне проекта и распакованного патча. Проверка несовпадения исходных хешей останавливает установку до первой записи. Не обходить её сбросом Git: проверить, какой файл отличается.
В 11C новые зависимости не добавлены; установленного `node_modules` от 11B достаточно. После получения проекта через Git на другом компьютере выполнить `npm ci` и `npm run prisma:generate` как обычно. Миграция 11B должна уже быть применена, иначе история недоступна.

Если ZIP уже распакован поверх проекта, установщик `apply` повторно не запускать:

```cmd
node scripts\stage11c-patch.mjs verify .
npm run test:unit
npm run dev
```

Не генерировать новые VAPID-ключи: работающие ключи 11B и настройки `.env` сохраняются. Для работы истории `PUSH_ENABLED=true` не требуется.
Предупреждение Node об Experimental VM Modules в тестах не означает неуспешный тест.

## Локальная проверка покупателя

1. Закрыть все старые окна сайта и установленного приложения, затем открыть заново.
2. Войти именно покупателем и открыть `/account/notifications`. Административный вход не является клиентским входом.
3. Проверить историю, фильтр категории, «Только непрочитанные», «Показать ещё», отметку одного и всех сообщений.
4. Если после применения 11B для этого клиента событий ещё не было, пустой список корректен: старые заказы не превращаются задним числом в рассылку. На локальной базе создать обычный заказ через checkout и убедиться, что появилось новое сообщение даже без подключённого PUSH-устройства. Не добавлять демоданные в рабочую базу ради проверки.
5. Нажать «Открыть»: должна загрузиться соответствующая страница реального заказа/акции/товара, с серверной проверкой доступа.
6. В другом профиле браузера войти другим покупателем: его список и счётчик должны быть своими. Проверить выход, повторный вход и возврат кнопкой «Назад» — личная история запрашивается с сервера заново.
7. В настройках изменить категорию PUSH и проверить, что сохранённая история остаётся доступной; реклама включается/отзывается прежним отдельным согласием.
8. На телефоне открыть установленное PWA: нижние пять пунктов должны работать. В обычной вкладке нижнего меню нет. На настольном PWA оно появляется только при узком окне.
9. Проверить корзину после закрытия приложения, счётчик, отсутствие перекрытия кнопки оформления, избранное, повтор заказа и актуальный статус отдельного заказа.

## Автоматические проверки

```cmd
npm run test:unit
npm run test:inbox
```

Все тесты истории создают отдельный временный PostgreSQL WASM (PGlite), применяют SQL-миграции к нему и удаляют экземпляр после проверки. Они не используют `.env`/DATABASE_URL проекта для подключения к PostgreSQL и не отправляют почту/PUSH.

Для необязательных браузерных проверок на машине разработчика:

```cmd
npm install --no-save --package-lock=false playwright
npx playwright install chromium
npm run test:inbox-browser
npm run test:pwa-browser
npm run test:push-browser
```

Это инструмент проверки, зависимость Playwright в проект не добавлена. Скрипты создают свои данные и сервер на свободном loopback-порту. В новых проверках используются настоящие Express, cookies, авторизация, Prisma, SQL-триггеры и хранилище, а режим standalone эмулируется в браузере. Проверки 11B моделируют push-провайдер, не отправляют сообщения в Google/Apple/Mozilla.

## Android и iPhone — ручная проверка

Нужен HTTPS тестовый домен, либо компьютер с localhost для настольной проверки. `http://IP-компьютера` на телефоне не заменяет HTTPS для PWA/PUSH.

- Android Chrome: обычная вкладка без нижней панели; установка; пять пунктов в приложении; нижний жестовый отступ; клавиатура поиска/адреса; возврат из checkout без потери корзины; открытие сообщения заказа.
- iPhone Safari: установка через «Поделиться»; при необходимости первоначальный вход в отдельное хранилище установленного приложения; safe-area в портретной и альбомной ориентации; редактор/клавиатура; смена ориентации; переходы из истории.
- Для обоих: выключить интернет и убедиться, что видна нейтральная offline-страница, а персональные сообщения не показываются из кеша; восстановить сеть, проверить повторную загрузку.
- Для PUSH при продолжении ручного теста: действительные ключи 11B, разрешение браузера после нажатия, включённые уведомления ОС, отключённое «Не беспокоить»; отправку обрабатывает `npm run push:process` или уже настроенный таймер.

Физические Android/iPhone и внешняя доставка PUSH для 11C в этой среде не тестировались. Предыдущий тест владельца на Windows подтвердил реальную доставку 11B и переход на акции; это отдельная проверка, не доказательство тестирования iOS.

## Production Ubuntu — только после локальной проверки и явного подтверждения

Автоматического подключения или выкладки на VPS не было. Полный этап 11 требует совместного присутствия 11A/11B/11C в исходниках. ZIP 11C не является заменой полного проекта.

1. На `194.226.112.201`, в `/var/www/sibdel`, проверить действующую резервную копию по настроенной процедуре. Сохранить текущий SHA, `git remote -v`, `git status --short`, состояние PM2 и таймера PUSH. `.env` и uploads не копировать из ZIP. Проверить доступность нового кода в том репозитории, откуда фактически обновляется VPS: локальный push в Dimas-Shumil сам по себе не обновляет PabloAlligator.
2. Выбрать согласованное окно обновления. До замены кода остановить `sibdel-push.timer`, если он установлен, дождаться завершения текущего `sibdel-push.service` и остановить PM2 `sibdel`. Не заменять работающие исходники во время обработки отправки.
3. При использовании Git выполнить только fast-forward из подтверждённого remote и ветки main. Не использовать `reset --hard`, force push, автоматическое разрешение конфликтов или `git clean`. Либо применить этот ZIP проверенным установщиком поверх точной версии 11B, сохранив резервную копию вне проекта.
4. Выполнить `npm ci`, `npm run prisma:validate`, `npx prisma migrate status`. Если 11B уже установлен, новых ожидающих миграций от 11C нет. Если VPS ещё на 11A/старой версии, сначала выполнить подготовленный план 11B с проверкой назначения базы и резервного копирования; его единственная новая миграция добавляет таблицы/триггеры. Не использовать `db push`, reset или seed.
5. Выполнить `npm run prisma:generate`, `npm run test:unit`; запустить `pm2 restart sibdel --update-env`. Восстановить только ранее настроенный корректный PUSH-таймер. Новые unit-файлы или Nginx-конфиги 11C не нужны.
6. Проверить без вывода секретов:

```bash
cd /var/www/sibdel
pm2 status sibdel
curl --fail --silent --show-error https://sib-del.ru/api/health
curl -I https://sib-del.ru/account/notifications
curl -I https://sib-del.ru/sw.js
curl -i https://sib-del.ru/api/account/notifications
```

Первый health-запрос должен быть успешным; клиентский HTML — no-store/noindex; SW — no-store и версия 11c-1; API без клиентской cookie — 401 без истории. Дополнительно войти покупателем и проверить кабинет, переход к заказу, корзину, checkout, SEO и админку. Не вставлять cookies в общедоступные команды/логи. Смотреть только необходимые строки журналов без секретов.

## Откат 11C → 11B

В 11C нет изменения схемы. Прочитанные сообщения и существующие PUSH-данные совместимы с 11B; их не удалять и базу не восстанавливать поверх новых заказов ради отката интерфейса.

При установке через поставляемый установщик остановить локальный сервер и выполнить:

```cmd
node C:\Temp\sibdel-stage11c\scripts\stage11c-patch.mjs rollback "C:\Temp\sibdel-before-stage11c"
npm run test:unit
npm run dev
```

Установщик остановится до первой записи, если после установки файлы изменялись. Он восстанавливает прежние файлы и удаляет только добавленные этим патчем, не обращаясь к базе/.env/uploads. На VPS аналогично использовать сохранённую копию исходников 11B или согласованный обратный коммит без переписывания истории; восстановить зависимости из прежнего lock-файла и перезапустить приложение в том же порядке остановки.
Миграция `20261028110000_web_push` и файлы 11B остаются на месте. После отката закрыть все окна сайта/PWA, открыть заново: должен активироваться восстановленный worker 11b-1. Удалять все кеши домена, сбрасывать браузерное хранилище покупателя или отзывать рабочие VAPID-ключи не требуется.

Точный состав патча и SHA-256 до/после находятся в `STAGE11C-FILES.json`; результаты — в `STAGE11C-TEST-RESULTS.txt`.
