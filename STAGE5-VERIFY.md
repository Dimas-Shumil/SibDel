## Подтверждённые проблемы исходного архива

- На главной title был `Document`, description отсутствовал.
- robots.txt/sitemap.xml и обработчики этих URL отсутствовали.
- Карточка `/product.html?slug=...` до выполнения JavaScript содержала демонстрационный товар, цену и отзывы независимо от slug; отсутствующий товар не давал серверный 404.
- Каталог до JavaScript содержал демонстрационные товары, рейтинги, количество и пагинацию.
- Общий запрет индексации API, auth, кабинета и служебных страниц отсутствовал на уровне приложения. Проекты документов уже имели meta robots — они сохранены.
- Большинство тяжёлых PNG уже имели используемые WebP-версии: удалять исходники или конвертировать всё подряд не требовалось.
- Единственный используемый большой PNG среди найденных публичных ссылок: free-delivery.png (2 389 546 байт).
- Hero уже использовал адаптивные WebP, fetchpriority=high, decoding=async. CMS уже конвертировала загрузки в WebP quality 88, до 2400 px. Эти механизмы сохранены.
- Меню уже поддерживало Escape, aria-expanded, inert основной панели и возврат фокуса; вкладки товара — стрелки/Home/End. Добавлены недостающие части, без замены механизмов.

## Реализация

### Серверный HTML и URL

`middleware/seo.js` подключён после security/logger, до static и API.

- Каталог и карточка используют существующие `getPublicCatalog` и `getPublicProductBySlug`: расчёт Promotions, доступность и фильтрация не продублированы.
- Исходный HTTP HTML карточки содержит название, цену, описание, изображение/заглушку, характеристики, пищевую ценность и опубликованные отзывы из публичного сервиса.
- Исходный HTML каталога содержит актуальную подборку из 12 товаров и ссылки пагинации.
- Header/footer встроены в серверный HTML, а существующий клиентский загрузчик продолжает работать.
- JS продолжает подключать gallery, commerce, отзывы, фильтры и обновлять данные. До гидратации кнопка добавления товара отключена, чтобы не использовать демонстрационные ограничения количества.
- URL товаров остался `/product.html?slug=...`; новые пути и массовые замены ссылок не нужны.
- Нет slug, некорректный/повторяющийся slug или несуществующий/неактивный товар: HTTP 404 с noindex.
- Сбой сервиса/БД при SSR: HTTP 503 с noindex, без демонстрационного fallback. Это новая зависимость доступности каталога/карточек от БД; ответ не кэшируется.
- `/index.html` и `/index` перенаправляют на `/`; расширение `.html` добавляется к существующим публичным alias с сохранением query.
- Учитываются percent-encoded имена файлов: статическая выдача не обходит SSR.
- HTML-значения CMS экранируются; host-заголовок не используется для canonical/sitemap.
- Валидация запроса каталога вынесена в `utils/catalog-query.js` и используется существующим API. Для HTML совпадают браузерные defaults: available=1 при отсутствии фильтров доступности, limit=12.

### Индексация и метаданные

- Исправлены title/description главной; карточка получает seoTitle/seoDescription из CMS либо фактические название/краткое описание.
- Публичные страницы получают Open Graph title/description/type/locale. `og:url` и canonical появляются только при корректном `SEO_SITE_URL`.
- Для товара canonical сохраняет только slug; рекламные параметры не включаются.
- Каталог без фильтров: canonical учитывает page > 1, title содержит номер страницы. Несуществующая страница — 404.
- Каталог с категорией, поиском, сортировкой, фильтрами или неизвестными query: noindex, follow, без canonical. Это сознательная граница этапа: отдельные SEO-посадочные категории НЕ реализованы. Фильтры продолжают работать.
- Кабинет, auth, admin, API, components, cart/checkout/favorites и проекты документов получают X-Robots-Tag: noindex, nofollow; meta robots документов сохранён.
- robots разрешает обход, чтобы поисковик мог прочитать noindex. Robots и noindex не являются защитой данных; существующие auth/RBAC сохранены.
- `/sitemap.xml` — индекс: `/sitemap-pages.xml` и `/sitemap-products-N.xml`, по 1000 активных товаров активных категорий в файле, порядок id.
- В sitemap только 12 публичных основных URL и товары; нет кабинета, форм заказа, API, документов-проектов и фильтров.
- Не добавлены Product/Organization/LocalBusiness JSON-LD, рейтинги или адреса: в этом патче нет новых неподтверждённых структурированных данных. Расширенные результаты поиска не обещаются.

### Публичный домен

В `.env.example` добавлена НЕ секретная переменная:

```dotenv
SEO_SITE_URL=
```

После подтверждения домена записать его HTTPS origin в свой `.env` и перезапустить приложение. Например, формат значения: `https://ваш-подтвержденный-домен`, без пути, логина, пароля, query и hash. Не копировать этот пример как реальный адрес.

Пустая/неподходящая переменная не блокирует запуск и не меняет индексирование всех страниц: нет canonical/og:url и Sitemap в robots; sitemap endpoints возвращают 503 с noindex. APP_URL остаётся отдельным существующим адресом приложения для ссылок/безопасности. Никакой production-домен не придуман.

Для проверки sitemap локально на тестовом сервере можно временно задать `SEO_SITE_URL=https://seo-check.example` в CMD. Это только тестовый origin, не публиковать и не добавлять в основной `.env`.

### Доступность и тексты

## Недостающие сведения и границы запуска

- Подтверждённый production HTTPS-домен для SEO_SITE_URL; согласовать APP_URL отдельно при деплое.
